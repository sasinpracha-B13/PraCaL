# DEC-005 — ข้อมูลเงินเก็บใน IndexedDB ไม่ใช่ localStorage

**สถานะ:** accepted (2026-10-21) · **เกี่ยวกับ:** T-026b · [spec](../specs/T-026-money-tracking.md) §5.1, §5.7

## ปัญหา

ร่างสเปกเดิมเก็บข้อมูลเงินใน localStorage key `pracal_money_v1` และกันแท็บชนกันด้วย "อ่าน revision → ตรวจ → setItem"
ผู้ใช้ขอให้ตรวจช่องว่างระหว่างการตรวจกับการเขียนด้วยเบราว์เซอร์จริง ไม่ใช่ mock

## หลักฐาน (สองแท็บจริง · built-in browser · 2026-10-21)

| กลไก | รอบ | รายงานว่าสำเร็จ | เก็บจริง | หาย |
|---|---|---|---|---|
| localStorage อ่าน revision → setItem | 300 | 600 (สำเร็จทั้งคู่ทุกรอบ) | 300 | **300** |
| IndexedDB อ่าน-ตรวจ-เขียนใน readwrite transaction เดียว | 300 | 300 (อีกแท็บได้ "stale" ทุกรอบ) | 300 | **0** |

เหตุ: แต่ละแท็บ (process) ถือสำเนา localStorage ของตัวเอง การเขียนของอีกแท็บมาถึงแบบ async — ตรวจ revision ผ่านทั้งสองแท็บ แล้วเขียนทับกัน · การใส่ lock (Web Locks) ไม่แก้ เพราะสำเนาที่อ่านภายใต้ lock ยังอาจเก่าได้ · IndexedDB จัดคิว readwrite transaction ที่ทับกันให้ทีละอันข้ามทุกแท็บ และอ่านภายใน transaction ได้ค่าที่ commit แล้วเสมอ

## ตัดสินใจ

- ข้อมูลเงินอยู่ใน IndexedDB `PraCaLMoney` (store `state`, record `main` = `{ id, json }`) · `moneyCommit` อ่าน-ตรวจ stamp (`instance:revision`)-แก้-ตรวจกติกา-เขียน ใน transaction เดียว และรายงานผลหลัง `oncomplete` เท่านั้น
- ข้อมูลสุขภาพยังอยู่ใน localStorage `pracal_v1` ตามเดิม (ไม่อยู่ในขอบเขต · ปัญหาสองแท็บของฝั่งอาหาร F5 ยังเปิดอยู่)
- การกู้คืนเขียนสองที่เก็บที่ไม่มี transaction ร่วม: เขียนเงินก่อน แล้วสุขภาพ · ขั้นใดล้มเหลว คืนทั้งสองแล้ว**อ่านกลับมาตรวจ** · คืนไม่ครบ = แจ้งตามจริงและเก็บสำเนาไว้ให้กด "ย้อนการนำเข้า"
- ยังไม่มีผู้ใช้คนใดมีข้อมูลเงิน (ยังไม่มี UI) จึงไม่ต้อง migrate จาก localStorage

## ผลที่ตามมา

- ฟังก์ชันเก็บ/บันทึกเงินเป็น async · ส่งออกต้องอ่านเงินก่อน และ**ไม่ส่งออกถ้าอ่านเงินไม่ได้** (ไม่ปล่อยไฟล์ที่ขาดเงินแบบเงียบ ๆ)
- เบราว์เซอร์ที่ใช้ IndexedDB ไม่ได้ → ส่วนเงินใช้ไม่ได้ (แจ้งผู้ใช้) แต่ส่วนสุขภาพไม่กระทบ
- ทดสอบ: `tools/test-money-engine.js` ใช้ backend จำลองที่ทำ transaction ทีละอันตามคิว · ตรวจในเบราว์เซอร์จริงตาม spec §12
