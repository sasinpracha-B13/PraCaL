# T-022a.1 — Backfill body composition on past weight entries

**Status:** approved
**Owner:** Execution Agent
**Depends on:** T-022a (the `muscleMass_kg?`/`bodyFat_pct?` fields + `setWeight(…, extra)` semantics) · T-022b (charts that consume them)
**Related:** T-012 (waist) · the weight-log history list this extends

> Lets the user **add / edit / clear** `muscleMass_kg` and `bodyFat_pct` on **existing** `u.weights[]` entries (any entry that already has `weight_kg`), from the weight-log history rows. Today's main-input flow is untouched. Body-comp fields **only** — `weight_kg` and `date` are never editable here.

---

## 1. Goal

On the 📊 บันทึกร่างกาย history list, each weight entry gets an **edit affordance (✏️)** that opens **inline** inputs for muscle mass + body-fat only, prefilled with that entry's current values. This is how a user backfills body-comp onto older weigh-ins (or fixes/removes a wrong BIA reading) without re-logging or deleting the entry.

## 2. Why a new task (vs T-022a)

T-022a only writes body-comp onto **today's** entry via the main `#mm-input`/`#bf-input`, and its "empty = leave unchanged" rule means there is **no way to clear** a saved field. T-022a.1 adds (a) editing **past** entries and (b) an **explicit per-field clear** — the one place a wrong BIA value can be removed without deleting the whole day.

## 3. UI — inline edit on each history row

Current row ([index.html:6603](../../index.html)) shows date · optional 💪/🔥 read-back · `weight_kg` · 🗑️. Add an **✏️** button beside 🗑️:

```
[date]                         70.0 kg   ✏️  🗑️
   💪 35.0 กก. · 🔥 18.0%           ← existing read-back (unchanged)
```

Tapping ✏️ toggles the row into **edit mode** (tracked by `state.tmp.editingBodyComp = w.date`; tapping again or Cancel closes it). In edit mode the row expands to a minimal inline form:

```
[date]                         70.0 kg   ✖️
   💪 มวลกล้ามเนื้อ (กก.)   [ 35.0 ]  ✕      ← ✕ shown only when the field currently has a value
   🔥 % ไขมัน               [ 18.0 ]  ✕
   [ บันทึก ]  [ ยกเลิก ]
```

- Inputs `#bc-mm-<date>` / `#bc-bf-<date>`, `type="number" inputmode="decimal" step="0.1"`, **prefilled** with the entry's current `muscleMass_kg`/`bodyFat_pct` (empty if absent).
- Only **one row** edits at a time (`editingBodyComp` holds a single date). Opening another row replaces it.
- These inputs have unique ids not matched by the delegated `input` listener → **no re-render on keystroke**; values are read on Save. (Same mechanism as the main weight inputs.)
- `weight_kg`, the date, and 🗑️ delete are **not** part of this form.

## 4. Write path — new narrow helper `setBodyComp` (does NOT touch `setWeight`)

Per the scope lock, `setWeight` and its call sites are untouched. Add a scoped helper that patches body-comp on an **existing** entry only:

```js
// v1.10.50 — T-022a.1: apply a body-comp patch to an EXISTING weight entry (backfill/edit/clear).
// Never touches weight_kg or date, never creates an entry, never re-sorts (dates unchanged).
// Mirrors setWeight's `extra` semantics, per field in `patch`:
//   key present + number → set · key present + null → delete · key absent → leave unchanged.
// Returns true if an entry for `date` existed and was patched, else false.
function setBodyComp(user, date, patch) {
  const entry = ((user && user.weights) || []).find(x => x.date === date);
  if (!entry) return false;
  if ('muscleMass_kg' in patch) {
    if (patch.muscleMass_kg == null) delete entry.muscleMass_kg;
    else entry.muscleMass_kg = patch.muscleMass_kg;
  }
  if ('bodyFat_pct' in patch) {
    if (patch.bodyFat_pct == null) delete entry.bodyFat_pct;
    else entry.bodyFat_pct = patch.bodyFat_pct;
  }
  return true;
}
```

Guarantees: only the two body-comp keys change; `weight_kg`/`date` are read-only; a missing entry is a no-op (never creates). Rounding to 1 dp is done by the handler before calling (consistent with T-022a).

## 5. Validation (same semantics as T-022a, referenced to THAT entry's weight)

- `muscleMass_kg`: **> 0 and < that entry's `weight_kg`** (not today's weight, not profile weight — the row's own weight).
- `bodyFat_pct`: **3–70**.
- Invalid field → `toast(msg, true)` warning naming the field, and that field is **rejected** (not written) — the entry is never corrupted, other valid fields still save.
- Rounding: `Math.round(v * 10) / 10`.

## 6. Empty vs clear semantics

- **Blank input on Save = leave the field unchanged** (identical to T-022a — never a silent wipe).
- **Explicit clear = per-field ✕** shown next to a field only when the entry currently has that field. Tapping ✕ removes just that field immediately (`setBodyComp(u, date, { <field>: null })` → `persist()` → toast `ล้างค่า…แล้ว`), leaving the edit form open. This is the sanctioned way to delete a wrong BIA value without deleting the whole entry.

## 7. Handlers (all new; none modify existing handlers)

| `data-act` | Behavior |
|---|---|
| `edit-bodycomp` (`data-v=<date>`) | Toggle `state.tmp.editingBodyComp` between `<date>` and `null`; `render()` |
| `save-bodycomp` (`data-v=<date>`) | Read `#bc-mm-<date>`/`#bc-bf-<date>`; find entry (guard `weight_kg` present); build patch per §5 (filled+valid → set; filled+invalid → warn+reject; blank → omit key = leave); `setBodyComp`; `persist()`; close edit; `render()`; success/warn toast |
| `clear-bodycomp` (`data-v=<date>`, `data-field=muscle\|fat`) | `setBodyComp(u, date, { <field>: null })`; `persist()`; keep form open; `render()`; toast |
| `cancel-bodycomp` | `state.tmp.editingBodyComp = null`; `render()` |

`state.tmp.editingBodyComp` is view-scoped scratch (cleared on nav by `go`, like `chartSelection`). No persistence needed.

## 8. Charts (T-022b) — confirmed auto-pickup, no code change

The charts read `u.weights[]` directly and derive their series by filtering on the fields:
- Reports: `rangeMuscle = rangeWeights.filter(w => w.muscleMass_kg != null)` (+ fat), then `svgLineChart`/`dateWindowMean`.
- BPC: `renderBpcBodyCompCard` filters the same way.

A backfilled value simply makes that entry pass the filter → it appears in the chart on the next `render()`. **No chart code is touched.** (Verified at gate by grep: `svgLineChart`/`dateWindowMean`/`renderBpcBodyCompCard` byte-identical.)
