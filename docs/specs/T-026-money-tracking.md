## 1. ความเข้าใจ และความกำกวมที่พบ

**เป้าหมาย**
- **G1** ช่วงที่เลือก มีเงินเข้าและออกเท่าไร
- **G2** เงินออกไปกับอะไร
- **G3** ใช้เกี่ยวกับใคร (ตัวเอง / แฟน / เพื่อน / …) เท่าไร
- **G4** หนี้กินกระแสเงินสดเท่าไร และยังเหลือเท่าไร
- เงื่อนไข: จดเร็วบนมือถือ · แก้ย้อนหลังได้ · ไม่เชื่อมธนาคาร · ไม่กระทบข้อมูลสุขภาพ

**พฤติกรรมที่ออกแบบให้:** เปิดแอปทุกวันอยู่แล้ว · รายจ่ายส่วนใหญ่เล็กและซ้ำ (อาหาร เดินทาง) · บางครั้งจ่ายแทนเพื่อน/แฟน และบางทีเคลียร์รวมทีเดียว · มีหนี้ผ่อนอยู่เดิม และอาจซื้อผ่อนใหม่ · กลับมาดูสรุปเป็นรายสัปดาห์/เดือน

| # | ความกำกวม | ตัดสินใจ (ร่าง 2) |
|---|---|---|
| A1 | "รายรับ" ≠ "เงินเข้า" — เงินที่เพื่อน/ร้านคืนเป็นเงินเข้าแต่ไม่ใช่รายได้ | แสดง **รายรับ** (รายได้เท่านั้น) กับ **เงินคืน (ไม่ใช่รายได้)** แยกบรรทัด · ผลต่างใช้เงินเข้ารวม จึงเป็นกระแสเงินสดจริง |
| A2 | จ่ายหนี้นับเป็นค่าใช้จ่ายของฉันหรือไม่ | **ชนิดหนี้กำหนดกติกา ผู้ใช้ไม่ต้องตั้งเอง** (C1): **ผ่อนสินค้า** → เงินที่จ่ายจริงทั้งงวด (รวมดอกเบี้ย/ค่าธรรมเนียม) เป็นค่าใช้จ่ายในหมวดสินค้า ณ วันจ่าย ไม่สร้างยอดซื้อเต็ม · **เงินกู้ / ยืมเงิน / หนี้บัตรเดิม** → เงินต้นเป็นเงินออก + ลดหนี้ แต่ไม่เป็นค่าใช้จ่าย · ดอกเบี้ย/ค่าธรรมเนียมที่ทราบเป็นค่าใช้จ่ายหมวด "ดอกเบี้ย/ค่าธรรมเนียม" · ไม่สร้างรายจ่ายย้อนหลังชดเชยช่วงก่อนเริ่มใช้ — ระบบสรุปตามที่บันทึก ไม่ใช่บัญชีย้อนหลังครบถ้วน |
| A3 | ซื้อของผ่อนใหม่หลังเริ่มใช้ | **สร้างเป็นหนี้ในระบบเดียวกัน** (คำตัดสินข้อ 4) · วันซื้อ: หนี้ + ยอดคงเหลือ, เงินออกเฉพาะเงินดาวน์ที่จ่ายจริง · วันจ่ายงวด: เงินออก + หนี้ลด + ค่าใช้จ่ายของฉันตามการชำระ · ไม่มีตารางผ่อนอัตโนมัติ |
| A4 | "บริบท" = ไปกับใคร หรือซื้อให้ใคร | นิยามเดียว: **"ค่าใช้จ่ายนี้เกี่ยวกับใคร"** เลือกหนึ่งค่า · ไม่บอกว่าใครจ่าย — ส่วนนั้นอยู่ที่ "ส่วนของฉัน" |
| A5 | ร้านคืน / ไม่ได้รับคืน เกิดคนละเดือนกับวันซื้อ | **มีผลในวันที่เกิดเหตุการณ์** (คำตัดสินข้อ 5) — เดือนที่ปิดไปแล้วไม่ขยับ · ร้านคืน = ลดค่าใช้จ่ายของฉันในหมวดเดิม ณ วันได้คืน (หมวดติดลบได้ แสดง จ่าย/คืน/สุทธิ) · ยกให้ = เพิ่มค่าใช้จ่ายของฉัน ณ วันตัดสินใจ |
| A6 | "ของใช้จำเป็น" vs "ของฟุ่มเฟือย" ใส่การตัดสินคุณค่าลงในหมวด | ใช้ชื่อที่บอก "ซื้ออะไร": **ของใช้ประจำวัน / ช้อปปิ้ง** · มิติ จำเป็น/อยากได้ = Later |
| A7 | ยอดรวมรายวันในรายการใช้ตัวเลขไหน | เงินที่จ่าย/ได้รับจริงวันนั้น · แถวที่จ่ายแทนคนอื่นแสดง "ของฉัน ฿…" ใต้ยอด |
| A8 | สำรองจ่ายแล้วไม่ได้คืน | ปุ่ม **"ไม่ต้องคืนแล้ว"** = เหตุการณ์ไม่ใช่เงินสด มีวันที่ตัดสินใจ หมวด และบริบทของตัวเอง (ค่าเริ่ม = ของรายการเดิม) · ไม่สร้างเงินเข้า/ออก |
| A9 | ใบแจ้งหนี้กับการจ่ายวันเดียวกัน | ยอดตามใบแจ้ง = **ยอด ณ สิ้นวัน** (รวมการจ่ายวันนั้นแล้ว) · ยอดตั้งต้น = **ยอดก่อนการจ่ายที่จะบันทึกในแอป** · เตือนเมื่อชนวันกัน (§5.5) |
| A10 | ไม่รู้สัดส่วนเงินต้น/ดอกเบี้ย | **ไม่ตัดยอดเดา** · หนี้นั้นแสดง **"ยังไม่ยืนยันยอดหลังการชำระ"** + ยอดยืนยันล่าสุดและวันที่ + ยอดที่จ่ายไปหลังจากนั้น จนกว่าจะแยกงวด หรือใส่ยอดจากใบแจ้ง · **ไม่ใช้คำว่า "อย่างน้อย"** · เงินกู้ที่ยังไม่แยก: เงินออกเต็ม ไม่นับเป็นค่าใช้จ่าย และสรุปแสดง "ยอดชำระที่ยังไม่แยกเงินต้น/ดอกเบี้ย ฿X" + "ค่าใช้จ่ายที่สรุปยังไม่รวมดอกเบี้ยส่วนที่ไม่ทราบ" (C2) · หนี้ 0%: เงินต้นเติมให้ = ยอดจ่าย − ค่าธรรมเนียม (เห็นและแก้ได้ C4) |
| A11 | กู้คืนทั้งเครื่องหรือทีละโปรไฟล์ | รุ่นแรก **ทั้งเครื่อง** · ทีละโปรไฟล์ = Later · รูปความคืบหน้าไม่อยู่ในไฟล์สำรอง ต้องบอกชัด |
| A12 | บันทึกเงินย้อนหลังได้แค่ไหน | เงิน **ย้อนได้ไม่จำกัด** · **ห้ามวันที่ในอนาคต** · เหตุการณ์ที่ผูกกับรายการเดิม (คืน/ยกให้) ห้ามลงวันก่อนรายการเดิม |
| A13 | ยอดหนี้/ค้างรับในรายงานช่วงที่ผ่านมา | เป็นยอด **ณ วันที่** เสมอ และมีป้ายวันที่ทุกครั้ง: ช่วงที่จบแล้ว → "ณ สิ้นช่วง 31 ต.ค. 2026" · ช่วงที่มีวันนี้ → "ณ วันนี้ 21 ต.ค." · ห้ามแสดงยอดปัจจุบันในรายงานอดีตโดยไม่มีป้าย |
| A14 | ค่าใช้จ่ายของฉันของช่วงติดลบได้ไหม | ได้ (เช่นเดือนที่ได้เงินคืนก้อนใหญ่) · แสดงสุทธิพร้อม จ่าย/คืน แยกบรรทัดเสมอ ไม่ปัดเป็น 0 |

## 5. โครงสร้างข้อมูลและกติกาคำนวณ

### 5.1 การจัดเก็บ

```jsonc
// IndexedDB "PraCaLMoney" · store "state" · record { id: "main", json: <ข้อความด้านล่าง> }  (ไม่แตะ "pracal_v1") — DEC-005
{
  "schemaVersion": 1,
  "instance": "m…",                    // สุ่มครั้งแรกที่บันทึก · คู่กับ revision เป็น stamp ตรวจแท็บเก่า
  "revision": 0,                       // +1 ทุกครั้งที่เขียนสำเร็จ — ใช้ตรวจแท็บเก่า (§5.7)
  "byUser": {
    "<userId>": {
      "enabled": false,
      "categories": [{ "id": "c_food", "kind": "expense", "name": "อาหาร/เครื่องดื่ม", "order": 1, "archived": false, "system": null }],
```

- จำนวนเงินทุกตัวเป็น **สตางค์จำนวนเต็ม** · ไม่มีค่าลบในข้อมูล ทิศทางมาจากชนิดรายการ (ค่าลบเกิดได้เฉพาะผลคำนวณ เช่นหมวดสุทธิ)
- แปลงข้อความเป็นสตางค์ด้วยการแยกสตริง ไม่คูณทศนิยม · รับ `1200` `1,200` `1200.5` `1200.50` · สูงสุด ฿9,999,999.99
- วันที่เป็นสตริงท้องถิ่น `YYYY-MM-DD` (F9) **ไม่แปลงผ่าน UTC** · `createdAt` / `updatedAt` ไว้ตรวจสอบ ไม่ใช้จัดช่วง
- เวลาบันทึกล่าสุดของไฟล์สำรองอยู่ที่ `pracal_last_backup_at` (ทำแล้วใน T-026a) ไม่อยู่ใน key นี้

### 5.2 รายการเงิน (`txn`)

ทุกชนิดมี `id` · `kind` · `date` · `amount` > 0 · `note?` · `createdAt` · `updatedAt`

| ชนิด | ฟิลด์เพิ่ม | เงินสด | ค่าใช้จ่ายของฉัน |
|---|---|---|---|
| `expense` รายจ่าย | `categoryId` · `contextId` · `myShare` (0…amount ค่าเริ่ม = amount) · `owedBy?` · `debtId?` (= เงินดาวน์ของหนี้ซื้อผ่อน) | ออก `amount` | `+myShare` หมวด/บริบทของรายการ |
| `income` รายรับ | `categoryId` | เข้า | — |
| `moneyBack` เงินคืน | `backType`: `reimburse` (คนอื่นคืน) \| `refund` (ร้านคืน) · reimburse: `allocations: [{ txnId, amount }]` (หลายรายการ · ว่าง = ไม่ผูก) · refund: `allocations: [{ txnId, mine, others }]` (≤ 1 รายการ · `others` > 0 เฉพาะรายการที่จ่ายแทนคนอื่น) | เข้า เต็มจำนวน | refund: `−mine` ในหมวด/บริบทของรายการต้นทาง ณ `date` ของเงินคืน · `others` และ reimburse: — |
| `payOut` คืนเงินให้คนอื่น | `sourceTxnId` (รายการที่มียอดต้องคืน) | ออก | — (ไม่ใช่ค่าใช้จ่ายของฉัน) |
| `writeOff` ไม่ต้องคืนแล้ว | `sourceTxnId` · `categoryId` · `contextId` (ค่าเริ่ม = ของต้นทาง) | **ไม่มี** | `+amount` ณ `date` (วันตัดสินใจ) |
| `debtPayment` จ่ายหนี้ | `debtId` · `principal` · `interest` · `fee` (ทั้งสามเป็น `null` = ยังไม่แยก หรือครบทั้งสามและรวม = amount) | ออก | ตาม §5.4ข |

`writeOff` เป็นรายการแยก (ไม่ใช่ฟิลด์ในรายจ่าย) เพื่อให้มีวันที่/หมวด/บริบทของตัวเอง และลิงก์กลับต้นทางได้ (P12)

### 5.3 หนี้ (`debt`)

`id` · `name` · `type`: `installment | loan | card | personal` (กำหนดกติกาการนับ — ไม่มีสวิตช์แยก · C1) · `interestFree` · `categoryId?` · `contextId?` (จำเป็นเมื่อ `installment`) · `originDate?` (วันที่ก่อหนี้ — แสดงผลเท่านั้น) · `purchase?`: `{ price, downPaymentTxnId? }` (เฉพาะซื้อผ่อนในแอป) · `installment?` · `dueDay?` · `note?` · `history`: `[{ at, field, from, to }]` (เปลี่ยนชนิด/หมวด/บริบท — C7) · `status`: `active | closed | archived` · `anchors`: `[{ id, type: start | statement | adjust | close, date, balance, note?, waived? }]`

- **วันเริ่มติดตาม** = วันของ anchor `start` · ต่างจาก `originDate` (ผ่อนมือถือที่ซื้อ มิ.ย. แต่เริ่มติดตาม 1 ต.ค.)
- `adjust` = แก้ยอดตามที่ผู้ใช้รู้ (ไม่มีใบแจ้ง) · มีประวัติเหมือน `statement` · **ไม่สร้างรายการเงินใด ๆ**

### 5.4 กติกาคำนวณ — คำนวณสดทั้งหมด ไม่เก็บยอดสะสม (P4)

**ก. มุมเงินสด ช่วง [S, E]** — นับตาม `txn.date`
- รายรับ = Σ `income` · เงินคืน = Σ `moneyBack` · **เงินเข้า** = รายรับ + เงินคืน
- จ่ายค่าใช้จ่าย = Σ `expense.amount` (เต็มจำนวน รวมส่วนที่สำรองให้คนอื่น และเงินดาวน์) · จ่ายหนี้ = Σ `debtPayment.amount` · คืนเงินให้คนอื่น = Σ `payOut` · **เงินออก** = สามอย่างรวมกัน
- `writeOff`, ยอดหนี้ตั้งต้น, ราคาเต็มของซื้อผ่อน, ใบแจ้ง/ปรับยอด, ส่วนลดปิดหนี้ **ไม่อยู่ในมุมเงินสด**
- **ผลต่าง** = เงินเข้า − เงินออก · ป้าย "ผลต่างเข้า − ออก · ไม่ใช่ยอดเงินในบัญชี" เสมอ

**ข. ค่าใช้จ่ายของฉัน ช่วง [S, E] — ตามการชำระ ทุกบรรทัดลงวันที่ของเหตุการณ์ตัวเอง**

| เหตุการณ์ใน [S, E] | บรรทัด | หมวด · บริบท |
|---|---|---|
| `expense` | `+myShare` | ของรายการ |
| `writeOff` | `+amount` | ที่เลือกตอนตัดสินใจ |
| `moneyBack` refund | `−mine` | ของรายการต้นทาง |
| `debtPayment` หนี้ผ่อนสินค้า | `+amount` (ทั้งงวด รวมดอก/ค่าธรรมเนียม · แยกหรือไม่ก็เท่ากัน) — เงินต้น/ดอกเบี้ย/ค่าธรรมเนียมยังเก็บแยกในรายการ และแสดงในกล่อง "จ่ายหนี้ในช่วงนี้" โดยไม่บวกซ้ำ (การตีความ 1 · ยืนยันแล้ว) | ของหนี้ |
| `debtPayment` เงินกู้/บัตรเดิม/ยืม ที่แยกแล้ว | `+interest + fee` (เงินต้น 0) | "ดอกเบี้ย/ค่าธรรมเนียม" · ตัวเอง |
| `debtPayment` เงินกู้/บัตรเดิม/ยืม ที่ยังไม่แยก | 0 — สรุปแสดง "ยอดชำระที่ยังไม่แยกเงินต้น/ดอกเบี้ย ฿X" | — |
| reimburse · refund ส่วน `others` · `payOut` · เงินคืนไม่ผูก · ใบแจ้ง/ปรับยอด · ส่วนลดปิดหนี้ | 0 | — |

- ค่าใช้จ่ายของฉัน = Σ บรรทัด · **ติดลบได้** (A14) · แยกหมวด: แสดง จ่าย (Σ บรรทัดบวก) · คืน (Σ บรรทัดลบ) · สุทธิ
- บรรทัดกระทบยอด: จ่ายค่าใช้จ่าย − ส่วนของคนอื่น + ไม่ต้องคืนแล้ว − ร้านคืน (ส่วนของฉัน) + งวดผ่อนสินค้า + ดอกเบี้ย/ค่าธรรมเนียมของเงินกู้ · ติดลบได้ พร้อมคำอธิบาย (C8)
- **ผลที่ตามมา: เหตุการณ์หลังวันที่ E ไม่เปลี่ยนตัวเลขของช่วง [S, E]** — เดือนที่ปิดแล้วนิ่ง · ตัวเลขอดีตเปลี่ยนได้เฉพาะเมื่อแก้/ลบรายการที่ลงวันในอดีต (แก้ข้อมูลผิด — คำตัดสินข้อ 5)
- **ไม่นับซ้ำ:** ราคาเต็มของซื้อผ่อนไม่เคยเป็นบรรทัด · ดาวน์นับครั้งเดียวในฐานะ `expense` · งวดนับครั้งเดียวในฐานะ `debtPayment`

**ค. ยอดกับคนอื่นต่อรายการ ณ วันที่ t (ค้างรับ / ต้องคืน)**
- `pos(e, t)` = (`amount` − `myShare`) − Σ reimburse → e − Σ `writeOff` ของ e − Σ refund.`others` → e + Σ `payOut` ของ e (ทุกตัวที่ `date ≤ t` · e ที่ `date ≤ t`)
- `pos > 0` = **ค้างรับ** · `pos < 0` = **ต้องคืน** (ฉันถือเงินของคนอื่น)
- ค้างรับ ณ t = Σ max(pos, 0) · ต้องคืน ณ t = Σ max(−pos, 0) · แสดงแยก ไม่หักกลบข้ามรายการ · มีป้ายวันที่ (A13)
- ตัวอย่าง C5 — จ่าย 1,200 ส่วนฉัน 600 ร้านคืนทั้งหมด (mine 600 / others 600): **A** เพื่อนยังไม่คืน → pos 600 − 600 = 0 (ล้างค้างรับ) · **B** เพื่อนคืนแล้ว 600 → pos 600 − 600 − 600 = −600 (ต้องคืนเพื่อน 600) → payOut 600 → 0 · ทั้งสองกรณี เงินเข้าจากร้าน 1,200 · ค่าใช้จ่ายของฉัน −600

**ง. ยอดหนี้ ณ วันที่ t**
- จุดตัดของ anchor: `start` → ก่อนการจ่ายที่ลงวันเดียวกัน · `statement` / `adjust` / `close` → สิ้นวัน
- A = anchor ล่าสุดที่จุดตัด ≤ t · P = การจ่ายที่ลงวันหลังจุดตัดของ A จนถึง t
- ถ้าทุก p ใน P มี `principal` → **ยืนยันแล้ว**: balance(t) = A.balance − Σ principal
- ถ้ามี p ที่ `principal = null` → **ยังไม่ยืนยันยอดหลังการชำระ**: แสดง A.balance + วันที่ของ A + Σ amount ของ P · **ไม่แสดงยอดคงเหลือเป็นตัวเลข** · ไม่ใช้ "อย่างน้อย"
  เหตุผล: ยอดจริง = A − เงินต้นที่ตัดไป + ดอกที่งอกเพิ่ม ซึ่งไม่ทราบทั้งคู่ ขอบล่างที่พิสูจน์ได้จึงไม่มีสำหรับหนี้มีดอก (หลัก DEC-004)
- หนี้รวม: ถ้าทุกหนี้ยืนยัน → ผลรวม · ถ้าไม่ → **"รวมที่ยืนยันแล้ว ฿X · ยังไม่ยืนยัน N หนี้ (ไม่รวม)"** ไม่มีผลรวมทั้งหมด (§10 C3)
- อัปเดตจากใบแจ้ง/ปรับยอด = เพิ่ม anchor · แสดงข้อเท็จจริง "ตั้งแต่ยอดก่อนหน้า: จ่ายไป ฿3,000 · ยอดลดลง ฿2,550" · **ไม่สร้างเงินสด ไม่เดาแยกดอกย้อนหลัง ไม่นับเป็นค่าใช้จ่าย**
- ปิดหนี้ = anchor `close` ยอด 0 · ต้องยืนยันยอดก่อน (แยกงวดหรือใส่ใบแจ้ง) · `waived` = ยอดที่เหลือหลังการจ่ายวันนั้น (ส่วนลด — ไม่ใช่เงินสดและไม่ใช่ค่าใช้จ่าย)

**จ. ซื้อผ่อนใหม่ (commit เดียว ทั้งหมดหรือไม่มีเลย)**
- สร้าง `debt` (`type: installment`, `countAsMyCost: true`, หมวด/บริบทจากฟอร์ม, `originDate` = วันซื้อ, `purchase.price`) + anchor `start` วันซื้อ ยอด = ราคา − ดาวน์
- ถ้าดาวน์ > 0 → สร้าง `expense` ยอดดาวน์ หมวด/บริบทเดียวกัน `debtId` ชี้หนี้ · หนี้เก็บ `downPaymentTxnId` (ลิงก์สองทาง)
- ไม่มีดาวน์ (0% × 12 ราคา 12,000): หนี้ 12,000 · เงินออกวันซื้อ 0 · ค่าใช้จ่ายของฉันวันซื้อ 0

**ฉ. ช่วงวันที่**
- วันนี้ · สัปดาห์นี้ = จันทร์–อาทิตย์ที่มีวันนี้ · เดือนนี้ · เดือนก่อน · กำหนดเอง (รวมทั้งสองวัน · สิ้นสุดก่อนเริ่ม = บล็อก)

### 5.5 กติกาตรวจ (บล็อกหรือเตือนพร้อมข้อความ) — ตรวจทั้งตอนสร้าง แก้ และลบ ข้ามรายการที่ผูกกัน

| กติกา | ผล |
|---|---|
| 0 ≤ `myShare` ≤ `amount` | บล็อก |
| Σ reimburse(e) + Σ writeOff(e) ≤ `amount` − `myShare` (ทุกวันที่) | บล็อก "ได้รับคืนแล้ว ฿300 — ส่วนของฉันสูงสุดได้ ฿900" |
| refund: `mine + others` ≤ ยอดเงินคืน · Σ `mine` → e ≤ `myShare` + Σ writeOff(e) — **ณ วันที่คืนแต่ละครั้ง** = ค่าใช้จ่ายสุทธิที่ยังเหลือของรายการ (การตีความ 2 · ยืนยันแล้ว) | บล็อก "ส่วนของฉันคืนได้สูงสุด ฿600" · คืนก่อนวันยกให้ → นับเฉพาะที่ยกให้แล้ว ณ วันนั้น |
| refund: Σ `others` → e + Σ writeOff(e) ≤ `amount` − `myShare` · `others` > 0 เฉพาะรายการที่จ่ายแทนคนอื่น | บล็อก "ส่วนของคนอื่นในรายการนี้มี ฿600" |
| `payOut` ≤ ยอดต้องคืนของรายการ ณ วันที่จ่าย | บล็อก "ต้องคืนรายการนี้ ฿600" |
| `writeOff` ≤ ค้างรับของรายการ ณ วันตัดสินใจ | บล็อก |
| เงินคืนก้อนเดียว: Σ allocations ≤ amount | บล็อก "จัดสรรเกินยอดที่ได้รับ" |
| แต่ละ allocation ≤ ค้างรับคงเหลือของรายการนั้น | บล็อก "เกินยอดค้างรับของรายการ 31 ต.ค. (฿400)" |
| Σ allocations < amount | ยืนยัน "เหลือ ฿100 ไม่ได้จัดสรร — จะเก็บเป็นเงินคืนที่ไม่ผูก (ไม่ใช่รายได้)" |
| เงินคืน / ไม่ต้องคืนแล้ว ลงวันก่อนรายการต้นทาง | บล็อก "วันที่ต้องไม่ก่อนวันจ่าย (10 ต.ค.)" |
| วันที่ ≤ วันนี้ · วันจ่ายหนี้ ≥ วันเริ่มติดตาม | บล็อก |
| แยกงวด: principal + interest + fee = amount · หนี้ 0%: interest = 0 | บล็อก "รวมได้ ฿2,950 ไม่เท่ายอดจ่าย ฿3,000" |
| แก้งวดเดิม (เช่นแยกเงินต้นทีหลัง) | แสดงผลต่อรายงานช่วงเดิมก่อนบันทึก "ต.ค. 2026: ค่าใช้จ่ายของฉัน +450 · D2 ณ 31 ต.ค. กลายเป็นยืนยัน 27,450" (C2) |
| หนี้ยืนยันแล้ว: principal ≤ ยอดคงเหลือ ณ วันจ่าย | บล็อก "มากกว่ายอดคงเหลือ ฿8,000" |
| หนี้ยังไม่ยืนยัน | บันทึกได้ + แจ้ง "ตรวจกับยอดคงเหลือไม่ได้ เพราะยอดยังไม่ยืนยัน" |
| จ่ายลงวันที่ ≤ วันของใบแจ้ง/ปรับยอดล่าสุด | เตือน "ใบแจ้ง 10 พ.ย. ถือว่ารวมการจ่ายนี้แล้ว จะไม่ตัดยอดซ้ำ" + ปุ่ม "ใบแจ้งเป็นยอดก่อนจ่ายนี้ → เลื่อนวันใบแจ้งเป็นวันก่อนหน้า" |
| รายจ่ายหมวดเดียวกับหนี้ซื้อผ่อนที่ active และจำนวน = ยอดงวด ภายใน ±5 วันจากวันครบกำหนด | เตือน (ไม่บล็อก) "นี่คืองวดของ 'ทีวี' หรือเปล่า? → บันทึกเป็นจ่ายหนี้แทน" — กันนับงวดซ้ำเป็นรายจ่าย |
| ลบรายจ่ายที่มีรายการผูก | ยืนยันที่ระบุทีละรายการ: "เงินคืน ฿300 (8 พ.ย.) ยังอยู่ในเงินเข้า แต่ไม่ผูก" · "ไม่ต้องคืนแล้ว ฿300 (20 พ.ย.) จะถูกลบด้วย" · ดาวน์ของหนี้: "หนี้ 'ทีวี' จะไม่มีเงินดาวน์ผูก" |
| ลบ/แก้เงินคืน | allocations ไปตามรายการ · ค้างรับคำนวณใหม่ |
| ลบหนี้ที่มีการจ่ายแล้ว | ไม่อนุญาต — ให้ "ปิด" หรือ "เก็บ" |
| ลบหนี้ซื้อผ่อนที่ยังไม่มีการจ่าย | ถามว่าลบเงินดาวน์ที่ผูกด้วยหรือไม่ |
| เปลี่ยนชนิด / หมวด / บริบทของหนี้ | preview ช่วงวันที่ของงวดที่กระทบ + ผลต่อค่าใช้จ่ายของฉันรายเดือน → ยืนยัน → บันทึก `history` · แนะนำ "สร้างหนี้ใหม่" ถ้าเป็นหนี้คนละลักษณะ (C7) |
| ลบหมวด/บริบทที่มีประวัติ | ไม่อนุญาต — ให้ "ซ่อน" |

### 5.6 หมวดและบริบท

- อ้างอิงด้วย `id` · เปลี่ยนชื่อ = เปลี่ยนการแสดงผลทุกที่รวมประวัติ · ซ่อน = ไม่อยู่ในตัวเลือก แต่ประวัติและสรุปยังถูก · "อื่น ๆ" และ "ดอกเบี้ย/ค่าธรรมเนียม" ซ่อนไม่ได้ · แยกต่อโปรไฟล์
- **หมวดรายจ่ายเริ่มต้น (10):** อาหาร/เครื่องดื่ม · เดินทาง · ของใช้ประจำวัน · ช้อปปิ้ง · เกม/บันเทิง · บ้าน/บิล · สุขภาพ · ของขวัญ/ทำบุญ · **ดอกเบี้ย/ค่าธรรมเนียม** (`system: 'interest'` — ปลายทางของดอกเบี้ยที่แยกแล้ว) · อื่น ๆ
- **หมวดรายรับเริ่มต้น (4):** เงินเดือน · รายได้เสริม · โบนัส/พิเศษ · อื่น ๆ
- **บริบทเริ่มต้น (6) — "เกี่ยวกับใคร":** ตัวเอง · แฟน · เพื่อน · ครอบครัว · งาน · อื่น ๆ

### 5.7 การบันทึกของส่วนเงิน

```
moneyCommit(mutate):                 (async · DEC-005)
  0  restore epoch เปลี่ยน → หยุด (restored-elsewhere) แท็บต้องโหลดใหม่
  ── ภายใน IndexedDB readwrite transaction เดียว (เบราว์เซอร์จัดคิวข้ามทุกแท็บ) ──
  1  อ่าน record ปัจจุบัน
  2  stamp (instance:revision) ≠ ที่แท็บนี้โหลดไว้ → ไม่เขียน (stale) · คืนข้อมูลล่าสุดให้แท็บ
     แจ้ง "มีการแก้จากหน้าต่างอื่น ตรวจแล้วกดบันทึกอีกครั้ง" — ฟอร์มยังอยู่
  3  next = mutate(สำเนา) · revision + 1 · ตรวจกติกา §5.5 ทั้งชุด → ผิด = ไม่เขียน (invalid)
  4  put
  ── จบ transaction ──
  5  oncomplete → สำเร็จ · abort (เช่นพื้นที่เต็ม) → write-failed: ที่เก็บและสถานะในแท็บไม่เปลี่ยน
```
- ฟอร์มสร้าง `id` ตั้งแต่เปิด → upsert → กดซ้ำได้รายการเดียว · ซื้อผ่อนสร้าง id ของหนี้ + ดาวน์ตั้งแต่เปิดฟอร์ม
- ทุกการเปลี่ยนแปลงที่กระทบหลายรายการ (ซื้อผ่อน · ลบรายจ่ายที่มี writeOff · เงินคืนก้อนเดียว) อยู่ใน commit เดียว
- หน้าจอรีเฟรชเมื่ออีกแท็บบันทึก (BroadcastChannel) — T-026c · ความถูกต้องไม่ขึ้นกับการรีเฟรช เพราะแท็บเก่าถูกปฏิเสธตอนบันทึก
- **ลบโปรไฟล์ (T-026b):** ลบ `byUser[id]` ก่อน (`moneyDeleteUserData` — transaction เดียว) · ไม่สำเร็จ → ไม่ลบโปรไฟล์ + แจ้ง · สำเร็จแล้วบันทึกสุขภาพไม่สำเร็จ → คืนข้อมูลเงินที่ลบ (`moneyPutUserData`) + คืน state ในหน่วยความจำ + แจ้ง "ลบโปรไฟล์ไม่สำเร็จ" · ขึ้น "ลบแล้ว" เฉพาะเมื่อทั้งสองส่วนสำเร็จ · ข้อความยืนยันบอกว่ารวมข้อมูลเงิน · `persist()` คืน true/false (ผู้เรียกเดิมไม่ใช้ค่า จึงไม่เปลี่ยนพฤติกรรม)

### 5.8 ไฟล์สำรองและการกู้คืน (T-026a — ทำแล้ว)

**ไฟล์สำรองเดิม (ตรวจจาก git):** โค้ด `export-data` **เหมือนกันทุกไบต์ตั้งแต่ v1.0.0 (`5907a41`) ถึง v1.10.53** ซองไฟล์เดียว: `{ version, exportedAt, users, currentUserId, customMeals, favorites, logs, dailyTargets }` · ที่ต่างคือรูปข้อมูลข้างใน ซึ่ง `migrateData()` จัดการ · ในเครื่องนี้ไม่มีไฟล์สำรอง JSON (มีแต่ CSV ซึ่งกู้คืนไม่ได้) → ไฟล์ทดสอบสร้างด้วย**โค้ดส่งออกจริงของ v1.0.0 และ v1.10.53** ที่รันในเบราว์เซอร์

```jsonc
{ "format": "pracal-backup", "formatVersion": 2, "appVersion": "v1.10.54", "exportedAt": "…",
  "health": { "users": [], "currentUserId": "", "customMeals": [], "favorites": [], "logs": {}, "dailyTargets": {}, "bpcRange": {} },
  "money":  null /* หรือเนื้อหา pracal_money_v1 ทั้งก้อน */ }
```
- **ไฟล์รูปแบบเดิม** ไม่มี `format` → ระบุจาก `users` (array) + `logs` + `version` แบบ `v1.*` → นำเข้าเฉพาะสุขภาพ ส่วนเงินว่าง · หน้าตัวอย่างบอกชัด "ไฟล์นี้ไม่มีข้อมูลเงิน — ข้อมูลเงินในเครื่องนี้ (N รายการ · หนี้ M) จะถูกลบทั้งหมด · ย้อนกลับได้ภายใน 7 วัน"
- **ข้อมูลเงิน (T-026b):** ส่งออกอ่านจาก IndexedDB ก่อน — อ่านไม่ได้ = ไม่ดาวน์โหลดและแจ้ง · นำเข้าตรวจกติกาเงินทั้งชุด (`moneyValidateUser`) ก่อนเขียน · ข้อมูลเงินของโปรไฟล์ที่ไม่มีในส่วนสุขภาพไม่ถูกนำเข้า และหน้าตัวอย่างบอกจำนวน · เขียนเงินก่อนแล้วสุขภาพ · ล้มเหลวขั้นใด คืนทั้งสองแล้วอ่านกลับมาตรวจ · คืนไม่ครบ → แจ้ง "คืนข้อมูลเดิมได้ไม่ครบ" + เก็บสำเนาให้กดย้อน
- **ปฏิเสธก่อนเขียน:** JSON เสีย · ไม่ใช่ไฟล์ PraCaL · ไม่มีโปรไฟล์ · เกิน 3 โปรไฟล์ · id ซ้ำ/ว่าง · ไม่มีชื่อ · ฟิลด์ที่ต้องเป็น array ไม่ใช่ · `logs`/วันที่/รายการผิดรูป · `formatVersion` หรือ `money.schemaVersion` ใหม่กว่าที่รองรับ · ไฟล์ > 20 MB
- **ขั้นตอน:** ตรวจ → ตัวอย่าง (เทียบไฟล์ vs เครื่อง + เตือน: ไฟล์มีอาหารน้อยกว่า · โปรไฟล์ที่จะหาย · ข้อมูลเงินในเครื่องจะถูกลบ) → สำเนา `pracal_v1` + `pracal_money_v1` ลง IndexedDB `PraCaLSafety` (เก็บ 7 วัน สูงสุด 3 ชุด · **ไม่แตะ** `PraCaLBodyProgress`) → เขียน `pracal_restore_epoch` → เขียนทีละ key ถือค่าเดิมไว้ · ล้มเหลว = เขียนกลับทั้งสอง + ลบสำเนา + แจ้ง → เครื่องหมาย "เพิ่งนำเข้า" (มี tabId) → epoch อีกครั้ง → โหลดใหม่
- **ตรวจหลังโหลด (เฉพาะแท็บที่กู้คืน):** `migrateData()` + render หน้าหลักแบบไม่แสดงผลของ**ทุกโปรไฟล์** · พัง → คืนจากสำเนาอัตโนมัติ + แจ้ง · แท็บที่กู้คืนหายไปเกิน 30 วินาที → แท็บอื่นรับช่วง · คืนซ้ำไม่ได้ (อ่านเครื่องหมายซ้ำก่อนคืน)
- **กันแท็บอื่นเขียนทับ (การแยก key อย่างเดียวไม่พอ):** แท็บอื่นฟัง event ของ epoch แล้วโหลดใหม่ · `persist()` เทียบ epoch ก่อนเขียนทุกครั้ง ไม่ตรง = ไม่เขียน + โหลดใหม่ (กรณีแท็บถูกพักแล้วพลาด event) — การแก้ `persist()` จุดเดียวของ T-026a
- **ไม่ได้ป้องกัน:** ล้างข้อมูลเว็บไซต์ / ลบแอป / มือถือหาย โดยไม่มีไฟล์สำรองนอกเครื่อง · persistent storage แค่ลดโอกาส · ไม่รวมรูปถ่ายความคืบหน้า

## 8. คำตัดสินของผู้ใช้ (บันทึกไว้ — ไม่ถามซ้ำ)

1. **ความเป็นส่วนตัว:** ไม่มี PIN/เข้ารหัสในรุ่นแรก · มีซ่อน/แสดงยอด จำสถานะ ซ่อนทุกจุดที่เกี่ยวข้อง · ไม่มีการ์ดเงินในหน้าสุขภาพ → §5.9
2. **หนี้:** รองรับ 0% และมีดอกตั้งแต่รุ่นแรก ไม่คำนวณดอกอัตโนมัติ · ใส่ยอดจ่าย + แยกเงินต้น/ดอกเบี้ย/ค่าธรรมเนียมได้ · ไม่ทราบสัดส่วน → เงินออกบันทึกได้ แต่หนี้ "ยังไม่ยืนยันยอดหลังการชำระ" + วันที่ยอดยืนยันล่าสุด · ไม่ใช้ "อย่างน้อย" · ไม่ตัดเต็มจำนวน · ปรับยอดตามใบแจ้งมีประวัติ ไม่สร้างเงินสดปลอม → §5.4ง
3. **เงินคืน:** คืนบางส่วน ทั้งหมด และก้อนเดียวจัดสรรหลายรายการ · ไม่ทำระบบลูกหนี้เต็ม · ไม่จัดสรรเกินยอดที่ได้รับหรือค้างรับโดยไม่บอก · ไม่ใช่รายได้ → §5.5
